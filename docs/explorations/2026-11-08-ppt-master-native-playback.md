# PPT-master native playback rejection

The live six-page PPT-master deck failed before starting teaching playback with
`本页包含尚未支持同步教学提示的动画，请使用原生放映`.
Its saved SDK timing contained basic zoom (entrance 23/16), fill color (emphasis
1/2) and lighten (emphasis 30/0). These are native PPT effects, independent of
the speech editor's generated cues. The teaching slideshow's preset allowlist
only covered the effects generated by its own speech-motion editor.

Allow these three additional finite whole-object presets through the existing
native completion adapter. Keep sequence, target, duration, repeat, rewind,
unsaved-edit, automatic-page-advance and embedded-media checks unchanged.
Color effects are not mapped to a speech pulse: they retain their original SDK
effect and properties.

`deckwise-teaching-slideshow.test.ts` replays the three live preset tuples,
asserts native advancement and waits for actual completion before narration.
Before the fix, all three cases fail with the live error; after it, all pass.
The slideshow, native-motion, attention, object-choice and sidebar suites pass
(88 tests), and the application type check passes.

Two further live failures were caught after removing the preset rejection:

- Host saved-object mappings identify leaves inside PPT-master groups, but
  preview lookup searched only top-level shapes. Traverse the actual SDK tree,
  require consistent group-parent membership and unique identity, and use the
  SDK's accumulated slide transform for child geometry. Native bindings still
  require ancestor entrances before revealing their children.
- The ten-second speech-task poll could render the sidebar during native
  preparation, before the narration timeline existed. Rendering calls
  `stopAudio`, which disposes the native slideshow. A live `EndDemonstration`
  stack identified the polling callback as the caller. Skip polling during
  playback preparation, and recheck playback/edit state after in-flight status
  requests before rendering. Both timer-order regression cases failed before
  this fix and pass after it.

Final bundled-editor smoke verification used the current real PPTX, with a user
gesture for audio playback. All four body pages finished their 6/8/4/8 native
effects and started existing audio with observed `currentTime > 0.5`. Page one
remained in preparation for eleven seconds before native advancement to cross
the polling interval. An earlier single-page check also observed its live
spotlight at 1.2 seconds. Exit restored the editor and left the PPTX unmodified.
This is a start-of-narration smoke check, not a complete listen-through of all
69 speech segments or question acceptance.

## Automatic playback and generated speech links

The earlier smoke advanced native steps manually. It did not establish automatic
whole-course playback. A follow-up real whole-course probe waited six seconds
without clicking: all six first-page effects remained idle and speech stayed at
zero. The unbound main sequence required teacher clicks before calling onReady.

Unlinked effects now advance automatically in saved click order, waiting for
actual SDK completion and respecting pause, transition and disposal state. This
applies to both a standalone main sequence and the unclaimed part of a speech
schedule. Only speech-owned effects wait for speech; static elements get no new
animation. The original saved timing and history are restored on exit.

Generated speech cues previously lacked an explicit start trigger, and the old
object-order fallback required every native effect to have a speech owner.
Accept legacy generated cues in the existing speech scheduler; resolve a unique
native effect on the target or its nearest animated group. Reuse its original
preset and duration instead of creating a second effect. Ambiguous effects remain
unclaimed page-entry effects. Preserve the existing fully bound legacy path and
explicit native-animation links. New Host audio adoption writes the start trigger
for generated motion cues. No audio regeneration is needed for legacy cues.

Regression checks include automatic unbound advancement/pause and mixed schedules
in unit tests, plus real-editor playback of a grouped native target and a separate
unlinked effect for legacy, generated and explicitly linked cues. The original
legacy-cue browser regression failed with "Generated speech cues were not
scheduled" before the scheduler fix.

The all-unlinked browser check initially stalled because its hand-built PPT
fixture omitted the main sequence's `onNext` condition. Adding the saved native
condition made the check pass without changing the playback implementation.
All three real-editor variants now pass. Targeted unit suites pass 91 tests,
including preservation of legacy canvas preview; the application type check and
production build pass. A combined run under concurrent browser-build load hit
the existing five-second undo-history test timeout; the isolated sidebar suite
passes all 59 tests without increasing its timeout.

The final production bundle was staged into the running Desktop and the same
clean PPTX reopened normally. An automatic per-page probe completed all
6/8/4/8 saved native effects and observed advancing original speech audio on
each body page, with no animation clicks. Exit restored saved timing. Host
attention generation and audio adoption pass 11 tests, and its binary builds;
the currently running Host process predates the new explicit trigger marker.
Legacy-cue compatibility is already active in the staged editor, so this deck
does not require regenerated audio or a data migration.

A final whole-course run clicked the normal lesson button once and continuously
played all four body pages into page five (Quiz), with 69 original media starts.
All 6/8/4/8 effects reached their actual native end state; there were no manual
animation/page advances. Exit restored every slide's saved timing and returned
to page one. Evidence: `/tmp/deckwise-native-whole-course-20261108.js` and
`/tmp/deckwise-native-whole-course-result-20261108.json`. Quiz answers and the
last interaction were not exercised in this animation regression run.
